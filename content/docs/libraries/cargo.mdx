### Requirement

1. You must have a well-written README to explain your project
2. Build something and share it!

You can ship your demo in one of the following methods:
1. Upload your library/application to https://crates.io/ (Your demo link should be your crate URL). You can check the details [here](#crates).
2. Build the application and put it on your repo GitHub Release (Your demo link should be the GitHub Release link)

If you are building a library, your README must include an example of usage and further explain how it could be
used by other people, and your library must be distributed on https://crates.io/.

<Callout type="info" title="Note for making an application">
    You might want to do both as each carry their own advantages. Building the application allows the user to
    easily try the application without building the project, however the amount of architecture/operation system
    you could build for would be limited. Therefore, building the application with an instruction in README to
    install it from https://crates.io/ could be more optimal as a hybrid solution.

    You could also use GitHub Action to build for multiple architecture and operation system, although that
    would be much more complex.
</Callout>

You would be able to select the options for installation. I would recommend proceed with standard installation.

After installing, you would have to restart the shell to load the `cargo` binary.

### Creating a project [step]

You can create a project with `cargo init`:

```shell
cargo init <project_name>
```

Alternatively if you want to create a library project, you can add `--lib` as argument

```shell
cargo init <project_name> --lib
```

### Adding dependency [step]
You can use `cargo add` and `cargo remove` to add/remove dependency. You can find all the different library available
in https://crates.io/.

For example:
```shell
cargo add serde
cargo remove serde
```

There are some common libraries that you might want to use:

- [serde](https://crates.io/crates/serde) for data serialization
- [tokio](https://crates.io/crates/tokio) for asynchronous runtime

### Write your code [step]

Your main file will either be in `src/main.rs` or `src/lib.rs`, depend on whether you are making an application or library.
Reference to https://doc.rust-lang.org/stable/ for resource to learn rust!

### Distributing to crates.io [step] [#crates]

1. Create an account on https://crates.io/, which would require you to sign in with your GitHub
account.

2. Go to the [API token page](https://crates.io/settings/tokens) in account settings to create an API token.

<Callout type="warning">
    Do not share the API token to anyone else, as they might able to upload any crates under your user, and can
    potentially upload malicious software.
</Callout>

3. Run `cargo login` on your machine and paste in the API token.
4. Make sure your `Cargo.tmol` included `name`, `version`, `edition`, `repository`, `authors`, `readme`, `description`,
`license` under `[package]`, as they are required to upload to https://crates.io/

For example:

```toml title="Cargo.toml"
[package]
name = "your_project"
version = "0.1.0"
edition = "2024"
repository = "https://github.com/your_username/your_project"
authors = ["your_username" ]
readme = "README.md"
description = "description"
license = "GPL-3.0"
```

5. Write your README (very important!)
6. Run `cargo publish`
7. Put your demo link for your crates and submit!


### Distribute to GitHub Release (Application only) [step]
1. Run `cargo build --release` to build the application in release mode
<Callout type="info">
    In cases where release mode take a long time to build, you might just want to use incremental debug build,
    or try to change the optimization configuration.
</Callout>
2. Find the executable under `target/`
3. Test locally if the executable run correctly
4. Upload your executable to GitHub Release, with note on what OS and architecture it built for
5. Put your demo link for your GitHub Release link abd submit!
