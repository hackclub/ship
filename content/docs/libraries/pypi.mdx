### Requirement

1. A well written README
2. Ship your project!

You can ship your demo in one of the following methods:
1. Upload your library/CLI to https://pypi.org/ (Your demo link should be your pypi URL). You can check the details [here](#pypi).
2. Build the application with `pyinstaller` or alternative and put it on your repo GitHub Release
(Your demo link should be the GitHub Release link)
3. For project that doesn't qualify the above options, you might want to check out one of the other documents
for more details requirement

If you are building a library, your README must include an example of usage and further explain how it could be
used by other people, and your library must be distributed on https://crates.io/.

<Callout type="info" title="Note for making an application">
    Your writer personal preference is to distribute it on pypi if it is a CLI :)
    In general, using `pyinstaller` or alternative might cause additional setup for some library, or might not work
    at all. Please test your application thoroughly before submitting it to avoid delay!
    Your application could be mark as malware by antivirus (frequently) so it is something good to note about.
</Callout>

            </CodeBlockTab>
            <CodeBlockTab value="macOS">
                ```shell
                curl -LsSf https://astral.sh/uv/install.sh | sh
                ```
            </CodeBlockTab>

                ```shell
                powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
                ```

            </CodeBlockTab>

        2. Install a preferred version of python (could be skipped on macOS/Linux)

        ```shell
        uv python install 3.13 --preview --default # Install 3.13 to the default version of Python
        ```

        If you choose this path, you will be taking an opinionated approach by using uv as both your Python version
        manager and your package manager. If you prefer not to use it for both, you should select the alternative path.
    </TabsContent>
    <TabsContent value="python.org">
        1. Download the installer from https://www.python.org/downloads/
        <Callout type="warning" title="If you are on windows">
            Do not install Python from Microsoft Store, and if you have already done so, it is recommended to remove
            it as it is known to cause issue sometimes. For example, when installing dependency that use C library.
        </Callout>
        2. Run the installer

        Note that for following this, command would frequently be platform dependent, it might be more recommended
        to use `uv` path instead, if possible.
    </TabsContent>
</Tabs>

### Creating a project [step]
<Tabs groupId="install-op" items={["uv", "python.org"]} persist defaultIndex={0}>
    <TabsContent value="uv">
        Run
        ```shell
        uv init project_name
        ```
    </TabsContent>
    <TabsContent value="python.org">
        1. Create your project directory and `cd` to the directory
        2. Initialize the virtual environment
        <CodeBlockTabs groupId="os" items={["macOS", "Linux", "Windows"]} persist  defaultValue="Linux">
            <CodeBlockTabsList>
                <CodeBlockTabsTrigger value="Linux">Linux</CodeBlockTabsTrigger>
                <CodeBlockTabsTrigger value="macOS">MacOS</CodeBlockTabsTrigger>
                <CodeBlockTabsTrigger value="Windows">Windows</CodeBlockTabsTrigger>
            </CodeBlockTabsList>
            <CodeBlockTab value="Linux">
                ```shell
                python3 -m venv .venv
                source .venv/bin/activate # This include all the necessary environment variable, you need to run this in each terminal session
                ```
            </CodeBlockTab>
            <CodeBlockTab value="macOS">
                ```shell
                python3 -m venv .venv
                source .venv/bin/activate # This include all the necessary environment variable, you need to run this in each terminal session
                ```
            </CodeBlockTab>
            <CodeBlockTab value="Windows">
                python -m venv .venv
                .\venv\Scripts\activate # This include all the necessary environment variable, you need to run this in each terminal session
            </CodeBlockTab>
        </CodeBlockTabs>
        3. Create `pyproject.toml`
        ```toml title="pyproject.toml"
        [build-system]
        requires = ["setuptools>=61.0"]
        build-backend = "setuptools.build_meta"

        [project]
        name = "project_name"
        version = "0.1.0"
        description = "project_desc"
        readme = "README.md"
        requires-python = ">=3.9"
        dependencies = []
        ```
        4. Create `README.md`
        5. Create `.gitignore` with https://github.com/github/gitignore/blob/main/Python.gitignore as its content
    </TabsContent>
</Tabs>

If you are making an application (CLI/GUI), add the following to your `pyproject.toml`
```toml
[project.scripts]
project_name = "project_name.module:entry_function"
```

(Please replace `project_name`, `module` and `entry_function` as appropriate)

### Distributing to pypi [step] [#pypi]
You should first create an account on [pypi](https://pypi.org/) and generate an API token.
<Tabs groupId="install-op" items={["uv", "python.org"]} persist defaultIndex={0}>
    <TabsContent value="uv">
        Use `uv version` to bump your project version

        Use `uv build` to build the package

        Use `uv publish --token your_secret_token` to publish it to pypi!

        You might alternatively want to set `UV_PUBLISH_TOKEN` environment variable to omit `--token your_secret_token`
        from the argument

    </TabsContent>
    <TabsContent value="python.org">
        On this stage, you would need 2 dependency: `build` and `twine`

        You would be asked for your username and password on `twine upload` stage, you should put

        Username: `__token__`

        Password: your API token

        You might have to update the version first before publishing, you can do so by editing the version
        on `pyproject.toml`

        <CodeBlockTabs groupId="os" items={["macOS", "Linux", "Windows"]} persist  defaultValue="Linux">
            <CodeBlockTabsList>
                <CodeBlockTabsTrigger value="Linux">Linux</CodeBlockTabsTrigger>
                <CodeBlockTabsTrigger value="macOS">MacOS</CodeBlockTabsTrigger>
                <CodeBlockTabsTrigger value="Windows">Windows</CodeBlockTabsTrigger>
            </CodeBlockTabsList>
            <CodeBlockTab value="Linux">
                ```shell
                pip install build twine
                python3 -m build
                python3 -m twine upload dist/*
                ```
            </CodeBlockTab>
            <CodeBlockTab value="macOS">
                ```shell
                pip install build twine
                python3 -m build
                python3 -m twine upload dist/*
                ```
            </CodeBlockTab>
            <CodeBlockTab value="Windows">
                pip install build twine
                python -m build
                python -m twine upload dist/*
            </CodeBlockTab>
        </CodeBlockTabs>
    </TabsContent>
</Tabs>

<Callout type="warning">
    Do not share the API token to anyone else, as they might able to upload any crates under your user, and can
    potentially upload malicious software.
</Callout>

### Distribute to GitHub Release with pyinstaller (Application only) [step]
1. Install `pyinstaller` and build the application
<CodeBlockTabs groupId="install-op" items={["uv", "python.org"]} persist>
    <CodeBlockTabsList>
        <CodeBlockTabsTrigger value="uv">uv</CodeBlockTabsTrigger>
        <CodeBlockTabsTrigger value="python.org">python.org</CodeBlockTabsTrigger>
    </CodeBlockTabsList>
    <CodeBlockTab value="uv">
        ```shell
        uv add --dev pyinstaller
        uv run pyinstaller --onefile main.py
        ```
    </CodeBlockTab>
    <CodeBlockTab value="python.org">
        ```shell
        pip install pyinstaller
        pyinstaller --onefile main.py
        ```
    </CodeBlockTab>
</CodeBlockTabs>
2. Find the executable under `dist/`
3. Test locally if the executable run correctly (very important!!! Please test the executable you built!!!)
4. Upload your executable to GitHub Release, with note on what OS and architecture it built for
5. Put your demo link for your GitHub Release link abd submit!
